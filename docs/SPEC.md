# Learning Platform: system spec

What the system does and how its parts fit. For how to work in each app see `backend/CLAUDE.md` and `frontend/CLAUDE.md`; for in-memory data see `docs/CACHING.md`.

## Purpose

One web system for a school's daily work and for math practice. A system admin onboards schools; each school's manager builds its structure (grades, classes, teachers, timetable); teachers send tests and messages; students practise with auto-generated questions, take timed tests and see their progress. There is also an AI tutor (ChatGPT) for every user.

## Parts

```
frontend/ (React, Vite)  ──REST + JWT──▶  backend/ (Spring Boot)  ──JPA──▶  MySQL
        ▲                                    │  ├─ SMS gateway (OTP codes)
        └──────────── SSE (/notifications) ──┘  ├─ SMTP (re-engagement and OTP email)
                                                └─ OpenAI Chat Completions (AI tutor)
```

Deployed on Render: frontend `schoolmanagmentsystem-z0m5.onrender.com`, backend `learning-project-server.onrender.com`. Both are built from this repository's committed code. One backend instance (all live state is in process memory).

## Roles

| Role (`enums/Role.java`) | Can |
|---|---|
| `SYSTEM_ADMIN` | add schools, assign and remove school managers, list schools, send messages to managers |
| `SCHOOLMANAGER` | add/remove grades and classes, assign/remove teachers and their teaching subjects, assign students to classes, build lessons (timetable), view class timetables, send messages, read the school's absence report (and receive unusual-absence alerts) |
| `TEACHER` | see own timetable, generate a test for chosen students (graded automatically), see results, send messages, write lesson pages, give homework and follow the submission board, open class challenges, set students' extra exam time, keep a question bank, keep a gradebook per class, run a live quiz in class, mark attendance and read absence reports |
| `STUDENT` | practise questions by subject/topic, build a self-practice test, take teacher tests, answer a live class quiz, see timetable, tests and statistics, read lessons (learn, practice, review), submit homework, follow a daily study plan before exams, see their own XP, streak and badges, and turn on read-aloud or the dyslexia font. A student not yet in a school sees a reduced menu. |
| `PARENT` | see each linked child's teacher-test grades, averages by subject, practice summary and skill levels; receive messages from teachers and the manager. Linked to children by the manager (or created by the bulk import). |

Everyone registers as a `STUDENT` with no school. The system admin turns a user into a school manager (`assignUserAsSchoolManager`, which refuses anyone who is no longer a student); a manager turns users into teachers of the school or puts students in a class. Roles are enforced by the API: URL rules per route group in `config/SecurityConfig.java`, and ownership checks (`@PreAuthorize` with `security/AccessGuard`) so a teacher reaches only their own classes and students, a student only their own tests and results, and a school manager only their own school. A system admin passes every ownership check. A `PARENT` reaches only `/parent/**` (plus messages, notifications and settings), and `ParentService` checks the parent-child link on every read. Every endpoint added by the improvement branches binds its `userId` / `teacherId` / `studentId` / `parentId` to the caller, or its `schoolCode` to the manager's school; the services keep their relation checks (teacher teaches the student, test belongs to the teacher).

## Domain model (main entities)

- `UserEntity` (base) → `StudentEntity`, `TeacherEntity`, `SchoolManagerEntity`, `SystemAdminEntity`.
- `SchoolEntity` (identified by `schoolCode`) → `SchoolGradeEntity` → `ClassRoomEntity` → students.
- `LessonEntity` (teacher, class, subject, day and hours) makes up `ScheduleEntity` timetables for classes, teachers and students.
- Questions: `QuestionEntity`, `PracticeQuestionEntity`, `TestQuestionEntity`, `StudentQuestionHistoryEntity`, `StudentProgressEntity`, `StudentStatisticsEntity`.
- Tests: `PracticeTestEntity` + `PracticeTestResultEntity` (student's own), `TeacherTestEntity` + `TeacherTestResultEntity` (assigned by a teacher), `TestEntity` / `TestResultEntity`.
- Exams (teacher tests taken under the server clock): `ExamAttemptEntity` (`exam_attempt`: start, deadline, seed, saved answers, status, score, tab-leave count), `ExamAttemptAnswerEntity` (`exam_attempt_answer`: graded answer per question, the input of item analysis), `ExamIntegrityEventEntity` (`exam_integrity_event`: tab and focus events). `TestQuestionEntity` carries the question `kind` and its options, key, tolerance, points and position; `TeacherTestEntity` carries title, publish state and time, template flag, A/B version label and group, source test and shuffle settings.
- `MessageEntity` (sender, recipient, title, body, `readAt`, `batchId` shared by the copies of one send, `threadId`, `parentMessageId`, `attachmentId`, `scheduledFor` + `pending`), `MessageAttachmentEntity` (file bytes, shared by a batch), `Session`.
- `AuditLogEntity` (`audit_log`: actor, impersonator, action, entity type and id, before, after, time, IP, school) and `SchoolFeatureFlagEntity` (`school_feature_flag`: school code, feature, on/off).
- Engagement: `StudentEngagementEntity` (XP total, streak), `StudentDailyActivityEntity` (XP per day), `StudentBadgeEntity`, `ClassChallengeEntity`.
- `StudyPlanTaskEntity`: one day's study task for a student ahead of a teacher test.
- `LessonContentEntity` (a teacher's lesson page: text, video embed, worked examples, linked to a subject/topic/sub-topic) and `LessonProgressEntity` (learned / practiced / reviewed per student). Different from `LessonEntity`, which is a timetable slot.
- `HomeworkEntity` (title, instructions, due date, assigned students) and `HomeworkSubmissionEntity` (content, time, late flag).
- `StudentAccommodationEntity`: extra exam time percent, read-aloud and dyslexia-font preferences.
- AI: `AiUsageEntity` (one row per AI call: user, school, feature, tokens, estimated cost), `AiConversationMessageEntity` (tutor chat, kept `ai.retention.days`), `AiQuestionDraftEntity` → `BankQuestionEntity` (approved drafts go into the teachers' question bank, `bank_question`, with `source = AI`), `AiRubricEntity` + `AiOpenAnswerEntity` (open questions graded by rubric), `TestAnswerRecordEntity` (each answer of a checked teacher test) and `TeacherInsightEntity` (weekly insight).
- Teacher tools: `BankQuestionEntity` (question bank: text, answer, optional options, subject/topic/level/grade tags, owner, school, shared flag, usage counters), `GradebookAssignmentEntity` + `GradebookGradeEntity` + `GradebookWeightEntity` (a class gradebook per teacher), `AttendanceRecordEntity` (one student, one timetable lesson, one date).
- Notification center: `NotificationEntity` (per-user history with `readAt`), `NotificationPreferenceEntity` (in-app / email / push per user), `PushSubscriptionEntity` (a browser's Web Push endpoint and keys).
- `CalendarTokenEntity`: the secret token in a user's `.ics` feed URL.
- `ParentEntity` (extends `UserEntity`, many-to-many `children` → `StudentEntity`, table `parent_student`).
- `SchoolYearEntity` (school, name, dates, active/closed) → `SemesterEntity`; `ArchivedStudentRecordEntity` is a by-value snapshot of each student taken when a year closes. `LessonEntity` has an optional `room`.
- Schema changes are Flyway migrations in `backend/src/main/resources/db/migration` (V2 holds every table and column the improvement branches added; production runs `ddl-auto=validate`); `docs/MIGRATIONS.md` explains them. That includes widening `user_entity.role` from a native ENUM so `PARENT` can be stored.

These entities reference students and teachers by `userId` string columns, not foreign keys. Their tables (`student_engagement`, `student_daily_activity`, `student_badge`, `class_challenge`, `study_plan_task`, `lesson_content`, `lesson_content_example`, `lesson_progress`, `homework`, `homework_student`, `homework_submission`, `student_accommodation`) are created by the Flyway migration `V2__improvement_branches.sql`.

## Main flows

**Login.** `POST /user/login` checks the password (salted SHA-256) and records a server-side "password verified" mark for 5 minutes; `send-otp` and `verify-otp` refuse without that mark. `send-otp` sends a 5-character code from `SecureRandom` by SMS to the phone stored for the user (the `phoneNumber` parameter is ignored); the code is valid 2 minutes, held in memory and single use, and 5 wrong codes discard it and the mark, so the password must be entered again. JWTs are signed with `JWT_SECRET` (Base64, at least 32 bytes; the `production` profile does not start without it). `verify-otp` sets two httpOnly cookies and returns no token in the body: `access_token` (JWT, 15 minutes, path `/`) and `refresh_token` (random 256-bit value, 7 days, path `/Learning-App/user`, stored only as a SHA-256 hash in `refresh_tokens`). Page scripts never see either token. `POST /user/refresh-token` rotates the refresh token (the old one is revoked; presenting a revoked one again after a 30-second grace revokes the whole family) and sets new cookies, or answers 401. `POST /user/logout` revokes the family and clears both cookies. A password reset revokes all of the user's refresh tokens. The frontend sends `withCredentials` and `X-Requested-With` on every axios request, validates the session through the session endpoint on page load, and refreshes once and retries on a 401. Cookie flags come from `auth.cookie.*` (production: `Secure`, `SameSite=None`; dev: `SameSite=Lax` over http). A state-changing request that carries an auth cookie without `X-Requested-With` gets 403 (CSRF guard, `CookieCsrfGuardFilter`). `Authorization: Bearer` is still accepted for Swagger and API clients. Password reset works the same way with a separate OTP.

**Rate limits.** `RateLimitFilter` (Bucket4j, in memory) limits login, OTP send, OTP verify, password reset (forgot + reset) per client IP and per user (JWT user, otherwise the `userId` parameter). Over the limit the API answers 429 with a Hebrew `errorCode` and `Retry-After`. Limits are set under `rate-limit.*` in `application.properties`.

**Practice.** The student picks subject → topic → exercise. `student/generate-question` (`StudentService.generateQuestionForPractice`, only for a student in a class) gets a question from `MathQuestionFactory`, which has 31 generators across integers, fractions, equations, complex numbers, vectors, matrices, analytic geometry, calculus and Hebrew word problems; `submit-answer` checks the answer and updates the student's progress and question history.

**Tests.** A student builds a practice test (subject, topic, difficulty, count, time limit) and the server grades it on submit. A teacher generates a test for selected students with a start time; each student gets a `NEW_TEST` notification over SSE and sees it in the tests table until it is taken and graded.

**Exams.** A teacher builds an exam in `/exam-builder` (`exam/create-exam`) from authored questions: multi-select, numeric with a tolerance, matching, ordering and short open answer (formulas typed with MathLive and shown with KaTeX; the server reads LaTeX numbers such as `rac{7}{2}`). Each kind is graded on the server (`service/exam/ExamGrader`), all or nothing. An exam can be published now, at a chosen time (`jobs/ExamSchedulerJob` publishes it and sends `NEW_TEST`), saved as a template, cloned (`exam/clone-exam`), or split into versions A and B with different question order. The student starts it with `exam/start-attempt`: the server records the start, fixes the deadline (scheduled start + time limit), and returns the questions without keys in an order shuffled per attempt from a stored seed (the same order on reload). Answers are autosaved (`save-answers`); `submit-attempt` after the deadline plus 30 seconds is rejected and the attempt is graded from what was saved; the scheduler grades attempts nobody submitted. Leaving the tab sends `integrity-event`, and the teacher sees the counts and the log in `/teacher-exams/:id/monitor`. `/teacher-exams/:id/analysis` shows the difficulty index (share correct) and the discrimination index (upper minus lower 27% by score) per question and flags questions that are too hard, too easy, weak or negatively discriminating. Grading also writes a `TeacherTestResultEntity`, so the student's tests table and statistics keep working. The old `teacher/check-teacher-test` endpoint is retired (it had no timer), and `test/get-test` returns no questions for teacher tests.

**Messages.** The sender chooses a recipient type (a class, a grade, all students, all teachers, teachers of a grade, all managers); a strategy in `strategy/message/` resolves the users. Each recipient gets a saved copy and a `SYSTEM_MESSAGE` notification (and, in production, an SMS). All copies of one send share a `batchId`; the sender sees per-batch read counts (`sent-messages`) and who read it when (`read-receipts`); a recipient opening a message marks it read (`mark-read`). Anyone in a conversation can reply (`reply`): the reply goes to the other side and keeps the `threadId`, and `thread` returns the conversation as that user sees it. A send can carry one attachment (up to 5MB, stored in MySQL, downloaded through `attachment` by participants only) and a `scheduledFor` time: the copies stay `pending` and hidden until `ScheduledMessagesJob` (every minute) delivers them. The `/messages` screen shows the paged inbox, the sent list with receipts and threads.

**Notifications.** Services publish a `NotificationEvent`; `NotificationEventListener` stores one `NotificationEntity` per recipient, pushes it over SSE (event id = notification id; `notifications/connect` takes the user from the access cookie, sent with `EventSource(..., {withCredentials: true})`, and has no `userId` parameter), and sends email or Web Push to users who turned those on in `/settings`. The client reconnects SSE with backoff (2s to 60s, and at once when the tab or network comes back) and then fetches what it missed with `notifications/list?afterId=<last seen>`. The navbar bell shows the unread count and the latest items; in-app pop-ups follow the user's in-app preference. Web Push needs `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` (and optional `VAPID_SUBJECT`) in the environment; without them push stays off and the switch is disabled.

**Calendar sync.** `calendar/token` creates (once) a random token and returns the feed path `/Learning-App/calendar/feed/<token>.ics`; calendar apps fetch it without a login. It lists a student's tests, or the tests a teacher created, plus Israeli holidays; `regenerate-token` revokes the old link.

**Search (Ctrl+K).** `search/global?q=` returns up to 5 hits per type, scoped by the user's role and school: schools for the system admin; students, teachers, classes and exams for a manager; students, classes and own exams for a teacher; own exams for a student. The palette also lists role actions (create an exam, send a message...). `search/students-page` is a paginated student directory.

**Languages.** The UI uses react-i18next with Hebrew (default, RTL), Arabic (RTL) and English (LTR); the choice is sent as `Accept-Language`, and server texts that go through `MessageSource` (`resources/i18n/messages*.properties`, read by `LocalizedMessages`) answer in the same language. Older services still return inline Hebrew.

**Offline and install.** The frontend is a PWA (manifest + service worker from `vite-plugin-pwa`). A student can save 10 questions of an exercise for offline practice; answers given offline are queued in IndexedDB and submitted when the connection returns.

**Timetable.** The manager adds lessons to a teacher for a class; overlaps are rejected. Class, teacher and student timetables are cached and evicted when a lesson is added.

**Adaptive learning.** Four tables back it (`review_item`, `topic_mastery`, `sub_topic_hint`, `test_answer_record`), plus `question_entity.difficulty_level` and `practice_question_entity.hints_used` / `points_earned`. Endpoints are in `ControllerConstants.Adaptive` under `/student` and `/teacher`.
- *Mastery (Elo).* Each student has a rating per sub-topic (starts at 1000). Generator levels 1-5 are fixed ratings 850-1450; after every practice or exam answer the rating moves by K·(outcome − expected), K 48 for the first 10 answers then 32. Practice picks the level closest to rating + 50 (`EloRating.pickLevel`). The skill map (`/student/skill-map`) colours a sub-topic red below 1000, yellow below 1200, green from 1200; the teacher's class view (`/teacher/class-skill-map`) shows only classes in the teacher's `teacher_classroom` rows.
- *Mistakes notebook (SM-2).* A wrong practice answer, a practice answer reached only through the full solution, and every wrong exam answer enter `review_item`, due the same day. Reviewing (`/student/review/answer`) grades a correct answer as quality 4 and a wrong one as 1 and reschedules with SM-2 (1 day, 6 days, then interval × easiness). Due counts use the Israel calendar day.
- *Hints.* Per sub-topic: hint 1, hint 2 and solution steps, edited by teachers (`/teacher/hint-template`), with built-in defaults (`HintService`). The student opens them in order (`/student/practice-hint`); the step is stored on the question and caps its points at 10 / 7 / 4 / 0 and its Elo outcome at 1 / 0.75 / 0.5 / 0. The full solution ends with the question's own answer.
- *Exam feedback.* Grading a practice or teacher test writes one `test_answer_record` per question. The client then posts the seconds spent per question (`/student/exam-question-times`, time accrues to the last focused answer field) and reads `/student/exam-feedback`: score, breakdown by sub-topic with average time, the class's accuracy per sub-topic and the teacher test's class average (only when at least 3 other students contributed), and a recommendation to practise the weakest sub-topic below 80%.

**Gamification.** Practice answers, practice and teacher tests, lesson steps, study-plan tasks and homework report to `EngagementEvents`, which adds XP, moves the daily streak (Israel time) and awards badges for real achievements: first activity, 3/7/30-day streaks, XP milestones, mastery of a sub-topic (skill level 5), a perfect test, five on-time homework, a finished lesson. It runs in its own transaction and swallows failures, so it never breaks the student's work. `engagement/get-summary` returns only the student's own data: level, streak, this week's XP against last week's, badges, and the class challenges. A teacher opens a class challenge (a combined XP target between two dates); students see only the class total. There is no leaderboard by design.

**Study plan.** `study-plan/get-plan` finds the student's upcoming, unsubmitted teacher tests and, the first time, writes one task per day from today until the day before the exam (at most 14 days; learn first, practice in between, review last; 10/15/20 minutes by difficulty, +5 when the exam is three days away or less). Tasks are kept, so adherence (done / due so far) is tracked per exam. Completing a task gives XP.

**Lesson pages.** A teacher writes a lesson (`lesson-content/*`) for a subject, topic and optional sub-topic, with text, a YouTube/Vimeo link (normalised server-side to an embed URL; any other host is rejected) and worked examples. Students of every class the teacher teaches see it and go learn → practice (opens `/exercises/<subject>/<topic>/<sub-topic>`) → review; each step is saved once and gives XP.

**Homework.** A teacher gives homework to whole classes they teach; the assigned students are fixed when it is created and get a `NEW_HOMEWORK` notification. Students submit (or resubmit) text; after the due date it is still accepted and flagged late. `HomeworkReminderJob` runs every 15 minutes and sends one `HOMEWORK_REMINDER` to students who have not submitted, once the due date is within 24 hours. The teacher board shows per student: submitted, late, missing or pending.

**Accommodations.** A teacher sets a student's extra exam time (0-100%); the exam screen (`TestSession`) adds it to every timer (practice and teacher tests), rounding up. The student turns on read-aloud (Web Speech API, `he-IL`, math symbols read as Hebrew words) and a dyslexia-friendly reading mode (`html.dyslexia-mode` in `App.css`: plain sans font, wider spacing). Teacher exams run under the server clock (`ExamAttemptService`), which adds the same extra time to the attempt's deadline; practice tests are timed only in the browser.

**AI.** Everything goes through `service/ai/AiGateway`: the provider (`AiProvider`, today `OpenAiProvider`, chosen by `ai.provider` / `ai.model`) needs `GPT_TOKEN` in the environment, and without it every AI screen answers with a Hebrew "not enabled" message. The gateway enforces a per-user daily quota, serves repeated one-shot prompts from the `aiPromptCache`, and records tokens and estimated cost per school. Routes under `/ai/**` need a valid JWT (the user is taken from it, never from a parameter) and `/ai/staff/**` needs a staff role: the first routes where `SecurityConfig` enforces roles.
- *Tutor* (`POST /ai/tutor/stream`, SSE events `delta`/`replace`/`done`/`error`): Socratic, knows the practice question, its hidden answer and the student's typed answer; replies that give the answer away are withheld. `ExamGuard` turns it off while a teacher test is open for the student and for test questions. Photos go to the vision model; voice is the browser's Hebrew speech recognition, with `POST /ai/tutor/transcribe` as fallback.
- *Safety*: `ContentSafetyFilter` runs before and after the model: distress gets a caring answer with the ERAN hotline (never sent to the model), explicit content and prompt injection are refused, ID numbers, phones and e-mails are redacted, student text is wrapped as data. Refused messages are flagged; school staff see only flagged messages (`/ai/staff/safety/flagged`). `AiRetentionJob` deletes conversations after `ai.retention.days` (30); students can delete theirs at any time.
- *Question generation*: a teacher prompt → JSON questions (text, exact answer, explanation) → drafts queue → edit / approve / reject → `BankQuestionEntity`.
- *Rubric grading*: the teacher publishes an open question with a rubric; students answer (`/ai/open-questions`), the AI suggests a score and reasoning, the teacher approves or changes it in one click; students see only approved scores.
- *Insights*: every graded exam stores each answer in `test_answer_record` (`ExamFeedbackService.recordExamAnswers`, shared with the adaptive exam feedback; teacher-test rows carry `teacherUserId`); `AiInsightsJob` (Sundays 07:00) computes struggling students by topic and suspicious questions (most students chose the same wrong answer) and asks the AI for a summary from pseudonymised numbers (S1, S2...).

**Question bank.** A teacher writes questions or imports them from CSV/Excel (`/question-bank/import`: header row in Hebrew or English, up to 1,000 rows, UTF-8 or Windows-1255), tags them by subject, topic, level and grade, and may share each one with the other teachers of the same school. Search filters by tag and text over the teacher's own questions plus the shared ones. Each question counts how many times it was asked in a live quiz, how many answers it got and how many were correct.

**Gradebook.** Per teacher and class: students x columns. Columns are the teacher's system tests given to the class (read-only, best score per student from the test results) plus assignments the teacher adds (exam, homework, quiz, project; a maximum score; a date) and fills in by hand. Category weights (default exams 60%, homework 40%) must sum to 100; the final grade is the weighted mean of the category averages the student has. `/gradebook/export` returns the table as a right-to-left .xlsx.

**Live quiz.** The teacher opens a quiz for a class (`/live-quiz/start`, 6-digit code), sends questions from the bank or typed on the spot, and closes each one to reveal the answer. Students answer from `/live-quiz` on their phones, one answer per question. State moves over the existing SSE stream (`LIVE_QUIZ_STATE` to students, `LIVE_QUIZ_RESULTS` to the teacher), and both screens also poll. Sessions are in memory only.

**Attendance.** The teacher picks a date, sees that day's lessons from the timetable, and marks each student present, absent, late or excused. When a save newly makes a student's absences in the last 30 days reach 3 (then 6, 9...), or makes half or more of a class (4+ students) absent from a lesson, the school manager gets a message (saved, plus `SYSTEM_MESSAGE` over SSE). Reports per student over a date range: a teacher sees the lessons they marked, a manager the whole school. Dates follow Israel time.

**School administration (manager).** Under `/school-manager/...` (`SchoolAdministrationController`):
- *Bulk import*: the CSV text is posted to `bulk-import/preview`, which returns every row with its errors (bad id/email/phone, duplicates in the file or the database, unknown class, unknown child) and warnings; `bulk-import/commit` re-validates the same file, creates the valid students, teachers and parents with a generated initial password, and returns those passwords once.
- *Dashboard*: `analytics` averages graded teacher tests by grade, subject, teacher, month (from the test's start time) and parallel class. The page exports to PDF through the browser's print dialog.
- *Timetable builder*: `timetable/lessons` lists the school's lessons; `timetable/check` reports teacher, class and room clashes; `timetable/save` creates or moves a lesson and refuses clashes; `timetable/delete` removes one.
- *School years*: years with semesters; `school-years/close` archives every student, then promotes each grade to the next level (by Hebrew letter value, `ז` → `ח`, parallel class kept) or graduates the top grade, in one transaction; `school-years/archive` reads the snapshot.
- *Parents*: `parents/link` turns a registered user with no school into a `PARENT` (or reuses one) and links them to a student of the school.

**Parents.** `/parent/children` and `/parent/child-overview` serve the parent dashboard; every read checks the parent-child link (the `PARENT` role is also required by `SecurityConfig`). Teachers and managers message parents with the recipient types `הורי-כיתה` (a class) and `כל-ההורים`. Attendance is not recorded by the system yet, so the parent view says so.

**Dashboard feed.** `upcoming-events` returns next lessons, tests and events for the user's role, built by the strategy for that role.

**Audit log.** Role changes (promote to manager or teacher, remove a teacher or manager, which delete and recreate the user row), teacher and student class changes, grade changes, added lessons, recorded teacher-test scores, impersonation and feature-flag changes call `AuditService.record`. `GET /audit-log/list` (filters: action, actor, entity type and id, dates, paging) serves the "יומן פעולות" screen: a system admin sees everything, a school manager only entries of their own school.

**System admin tools.** Impersonation (`POST /impersonation/start?targetUserId=`, admin only; `POST /impersonation/stop` with the impersonation token) issues a 30-minute token that acts as the user and carries the admin's id; the frontend shows a banner while it is active and every audit entry records the impersonator. `GET /system-admin/health` reports uptime, database status and latency, request and error counters, AI call counters and whether `GPT_TOKEN` is set, memory and active users. Per-school feature flags (`AI_CHAT`, `PRACTICE_TESTS`, `TEACHER_TESTS`, `MESSAGES`, all on by default) are set at `/system-admin/feature-flags` and checked by `security/FeatureFlags`; a disabled feature answers 403 with a Hebrew message.

## API

About 85 endpoints in 21 controllers, all under `/Learning-App`. The full list with parameters is in Swagger (`/swagger-ui.html` on a running backend); the path constants are in `backend/.../constants/ControllerConstants.java` and their frontend mirror in `frontend/src/constants/pages.constants.js`. Most responses are `BasicResponse { success, errorCode, data }`, where `errorCode` is a Hebrew message for the user. Requests that fail validation (missing or invalid parameters), framework errors and unexpected server errors return HTTP 4xx/5xx with an RFC 7807 `application/problem+json` body: `{ type, title, status, detail, errors?, success: false, errorCode }`, where `detail` (= `errorCode`) is Hebrew and `errors` maps each invalid field to its Hebrew message. `GET /actuator/health` is public; other Actuator endpoints need a `SYSTEM_ADMIN` token.

## Background work

Exam publishing and auto-submission every 30 seconds (`ExamSchedulerJob`), homework reminders every 15 minutes (`HomeworkReminderJob`), scheduled message delivery every minute (`ScheduledMessagesJob`), an SSE heartbeat every 25 seconds, re-engagement email to inactive users (`InactiveUsersJob`), JWT validation cache cleared every 2 hours, holidays refreshed daily, and a self-ping that keeps the Render free tier from sleeping; weekly AI teacher insights (`AiInsightsJob`, Sunday 07:00 Israel time) and the nightly AI retention cleanup (`AiRetentionJob`, 03:30).

## Past-exam simulations and the grade-target calculator [s08]

**Past-exam simulations (סימולציית בגרות).** A bank of past exams (`past_exam` → `past_exam_section` → `past_exam_question`, entities `PastExamEntity`, `PastExamSectionEntity`, `PastExamQuestionEntity`) is sat under full conditions: the exam's real duration on the server clock, the original sections (a section can count only its best N answers, as in a Bagrut choice section) and a rubric per question. `PastExamSeeder` fills an empty bank once with two sample exams generated by `MathQuestionFactory` (original practice exams in the Bagrut format, not copies of real exams). A sitting is an `exam_sim_attempt` (`ExamSimAttemptEntity`): start sets the deadline, answers are autosaved, a submission after the deadline plus the 30-second grace is graded from the saved answers, and an attempt left open is graded (or deleted when it has no answer) the next time the student lists or starts exams. Grading (`ExamSimGrader`): an expected answer splits into parts at top-level commas, each matched part earns points / parts in any order, numbers compare by value. Submitted answers move the student's mastery (`MasteryService.recordAnswer`). Score prediction (`ScorePredictor`, shown as "לפי הביצועים שלך, הציון הצפוי הוא 82 ± 6"): per question, the Elo chance of a correct answer from the student's sub-topic rating against the question's level gives an expected score and a Bernoulli variance; it is blended with the mean and spread of the student's past simulations with weight n / (n + 2); the margin is one standard deviation, widened when little of the material was practised, clamped to 3–25. The prediction is stored on the attempt and compared on the result screen.

**"What do I need?" calculator (מחשבון מה אני צריך).** The student enters a target final grade; `GradeTargetService` reads every gradebook of the student's class (one per teacher, through `GradebookService`, with the teacher's category weights) and `GradeTargetCalculator` solves for the uniform percent the student needs in every remaining column (the teacher's columns without a grade for the student, and system tests dated today or later). With the gradebook rule the final grade is linear in that percent, so the answer is exact; an impossible target reports the highest reachable grade in Hebrew, a secured target the lowest possible one. The certificate average (the mean of the subject grades) is solved the same way. No new tables.
